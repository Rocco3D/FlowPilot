# FlowPilot 0.1.5

Thank you for using FlowPilot! Your feedback and bug reports make it better with every release.

## Added

- **Projects.** A job can start a new Flow project, named or with the name Flow gives it: `--new-project [name]`, `newProject` in the HTTP API and the MCP server. In a terminal, a job with neither `--project` nor `--new-project` asks whether to continue the most recent project or start a new one; the MCP tools tell the assistant to ask you. Projects can be listed (`flowpilot projects`, `GET /projects`, `list_projects`) and deleted by exact name or id, always after a confirmation (`flowpilot delete-project`, `DELETE /projects/:project`, `delete_project`).
- **Media already in Flow** can be listed and downloaded again without generating anything: `GET /media` and `POST /media/download` in the HTTP API, `list_media` and `download_media` in the MCP server.
- An image job that fails after finding its results in Flow lists their ids in the error, so they can be downloaded instead of generated again.
- `upscale` accepts `original`.

## Changed

- **Download quality.** Without `upscale`, results are downloaded at the best quality your Flow plan offers: 4K when the plan has it, else the 1080p/2K upscale, otherwise the original. A quality asked for that Flow does not offer fails the job instead of downloading another one.
- Results are downloaded from Flow's viewer.
- With `showBrowser` on, the automation window opens on the left half of the screen.

## Fixed

- In a project with many media, a job could save an older result of the project instead of its own. Only the top of the grid counts now, where Flow shows the newest results.
- Downloading an upscaled result works, and a download counts only when the file is on disk and not empty.
- A project asked for by its exact name is found.
- When Flow's home shows "Error loading projects", FlowPilot reloads it instead of reading an empty grid.
- The CLI no longer waits forever for a service that does not answer, and starts the service from the build output whichever directory it runs from.
- `doctor`, `models` and `selftest` never touch the Flow page while a job is using it, and `doctor` compares each default model with the models of its own mode.
- `config get <key>` prints an empty line for a known key that is not set.

The full list is in [CHANGELOG.md](https://github.com/Rocco3D/FlowPilot/blob/main/CHANGELOG.md).

## What was verified

Live, on Windows 10 with a Google AI Pro account, in October 2026: image jobs in new and existing projects (one with 31 media), video jobs, downloads of media already in Flow at the default quality and as original, the media list, project creation, listing and deletion from the CLI, the HTTP API and the MCP server, and the CLI timeouts. On Google AI Pro, downloads cost no credits, upscale included.

Not verified: macOS and Linux, Google plans other than AI Pro, a project grid sorted otherwise than newest first, video jobs reading their result from the top of the grid, two projects with the same name, and Flow not saving the name of a new project.

## How to update

Run these commands in the `FlowPilot` folder:

```bash
git pull
npm install
npm run build
```

Then run `flowpilot service stop`, and restart your AI assistant if you use FlowPilot through MCP.
